# Mac disk-cleanup recommendations survey (for rosie)

Research question: what do IT/sysadmin writers and developer blogs commonly recommend
checking to reclaim disk space on a developer Mac, and in what order (by payoff / safety)?
This note surveys several sources and extracts a rough consensus ordering.

## What sources commonly list

Nearly every source lists the same rough set of "usual suspects." Grouped by theme:

| Category                          | Typical location                                              | Notes from sources                                  |
|------------------------------------|-----------------------------------------------------------------|------------------------------------------------------|
| Xcode DerivedData                  | `~/Library/Developer/Xcode/DerivedData`                        | Called out as "usually the biggest offender"          |
| Xcode device support / simulators  | `~/Library/Developer/Xcode/iOS DeviceSupport`, simulator runtimes | Old iOS version support files, unused runtimes        |
| Xcode Archives                     | `~/Library/Developer/Xcode/Archives`                            | Old app archives accumulate                            |
| Docker images/containers/volumes   | Docker.raw disk image (Docker Desktop)                          | Needs `docker system prune -a`, sometimes a reclaim step beyond prune |
| node_modules (scattered projects)  | per-project                                                      | Individually small, adds up across many old repos      |
| Rust/Cargo target dirs             | per-project `target/`                                            | Compilation artifacts, regenerable                     |
| Homebrew cache + old Cellar versions | `~/Library/Caches/Homebrew`, Cellar                            | `brew cleanup` (default skips files <120 days old)      |
| Language/package-manager caches    | npm, Yarn, pip/conda, CocoaPods, Gradle, Composer, Maven, Go, SPM | Generally smaller individually, "fully recoverable"     |
| Time Machine local snapshots       | APFS purgeable space                                             | Not user-visible in Finder; needs `tmutil` or a disk tool |
| Mail downloads/attachments         | `~/Library/Mail/`                                                | Grows over years, often overlooked                      |
| iOS/iPadOS device backups          | `~/Library/Application Support/MobileSync/Backup`                | 5-50 GB each if Finder-syncing a phone/tablet            |
| Browser caches                     | per-browser cache dirs                                           | Mentioned but rarely called a big win                    |
| Photos library                     | `~/Pictures/Photos Library.photoslibrary`                        | Mostly about "Optimize Mac Storage" / iCloud offload, not raw deletion |
| Trash                              | `~/.Trash`                                                       | Universally listed as first/trivial check               |
| Downloads folder / old installers  | `~/Downloads`                                                    | .dmg/.zip/.pkg installers "easy to forget"               |
| System Data / purgeable space      | macOS "System Data" storage category                             | Opaque catch-all; overlaps with several items above      |

Tools mentioned for finding large files/dirs generically: `ncdu` (CLI, via Homebrew),
DaisyDisk and OmniDiskSweeper (GUI visual disk-usage maps), and Apple's own
System Settings → General → Storage panel with per-category "More Info."

## Typical ordering by payoff

Sources converge on a similar order, though exact GB figures vary by writer and by how
long a given machine has been in use. Two blog posts gave explicit ranked lists; the rest
implied an order through the size ranges they quoted per category.

1. **Xcode DerivedData** — routinely cited as the single biggest, safest win for iOS/macOS
   developers: commonly 10-80 GB, fully regenerated by the next build. `rm -rf` is the
   standard remedy. This is the near-universal "clean this first."
2. **Docker Desktop (images/containers/build cache/Docker.raw)** — next biggest for anyone
   using Docker, quoted as 10-200 GB+. Requires `docker system prune -a`, and one source
   notes pruning alone does not always shrink the underlying `Docker.raw` disk image —
   a separate reclaim step is needed to get the space back from macOS's view.
3. **Scattered node_modules across old/unused repos** — individually 200 MB-2 GB each, but
   sources note this adds up to 5-100 GB total across many repos; treated as safe because
   `npm install` regenerates from lockfiles. Tools like `npkill` are recommended for
   interactively finding/removing them.
4. **Other language build caches (Cargo target/, Gradle, CocoaPods, pip/conda, Composer,
   Maven, Go, SPM)** — same "regenerable build artifact" logic as node_modules and Xcode,
   individually 1-50 GB, ranked after the above three because they're less universal
   (depends on stack) and often smaller in aggregate.
5. **Time Machine local snapshots** — called out separately as a distinct, high-payoff, low
   -risk category: one source reports 30-80 GB vanishing "immediately" after deleting
   snapshots via `tmutil listlocalsnapshots` / `tmutil deletelocalsnapshots`, because this
   space is largely invisible to Finder/`du` and only shows up as "purgeable" or "System
   Data." This is presented as safe since it only removes local backup checkpoints, not the
   backups themselves.
6. **Homebrew cache and old Cellar/cask versions** — `brew cleanup`, typically 1-15 GB.
   Ranked mid-to-low priority: smaller absolute payoff than the build-artifact categories
   above, but very safe and a five-second command.
7. **Mail downloads, iOS device backups, Downloads folder installers** — described as "easy
   to forget" rather than as top offenders; iOS backups can be large per-item (5-50 GB) but
   are less common today (most people no longer do Finder-based device backups) so they
   rank lower as a general recommendation, more as a "check if applicable" item.
8. **Browser caches, System Data purgeable cruft, Photos library** — generally the last
   items mentioned, smaller or harder to safely target automatically; Photos guidance is
   mostly about enabling "Optimize Mac Storage" / iCloud offload rather than deleting local
   files outright, so it's more of a setting than a one-shot cleanup action.
9. **Trash** — always mentioned, but treated as a trivial first-glance check rather than a
   meaningful source of reclaimed space on a developer machine (most Trash content is small
   compared to build caches).

## Cross-cutting recommendation from most sources

"Measure before you delete" is a near-universal caveat: several sources tell readers to run
`du -sh` per directory, or use ncdu/DaisyDisk to visualize usage, before picking a cleanup
target, rather than deleting reflexively. This suggests rosie's UX should default to a
usage report/dry-run before any deletion.

## Notes for rosie's prioritization

- The consistent "big four, safe to automate" tier is Xcode DerivedData, Docker prune,
  scattered node_modules/target dirs, and Time Machine local snapshots — these are the
  most repeatedly cited as both high-payoff and low-risk (regenerable build artifacts, or
  local backup checkpoints rather than the backups themselves).
- Homebrew cleanup is universally safe but smaller-payoff; good as a quick default-on item
  but not a headline feature.
- Mail/iOS-backup/Photos items are correctly "basics" people mention, but multiple sources
  frame them as conditional (only relevant if you use Mail heavily, sync a phone via Finder,
  etc.), so they read as optional/opt-in checks rather than always-run targets.
- No source suggested an automated tool should touch Photos library content directly, only
  Apple's iCloud-optimize setting — worth noting as an explicit non-goal / caution area.
